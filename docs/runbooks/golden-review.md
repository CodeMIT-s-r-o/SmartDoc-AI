# Runbook: review the golden set

The golden set (`eval/datasets/golden_v1.jsonl`, 40 items) is the reference that the quality
numbers are measured against. 30 of its items were generated by an LLM, so a person has to confirm
each one against the source page before any number counts. Until then:
- every item is `pending`;
- `make eval` refuses to run without `--include-pending`;
- CI runs with `--include-pending`, and its results say so.

**Time:** about 1–2 hours (2–3 minutes per item). **Cost:** $0, with no database or API key needed.

## Before you start

- **The corpus PDFs** must be in `eval/corpus/`. They are not committed; see
  [eval/corpus/README.md](../../eval/corpus/README.md). Check them with `make corpus-check`.
- **`make install`** must have been run once (uv).

## Start

```bash
make golden-review          # then open http://127.0.0.1:8766  (REVIEW_PORT=… to change the port)
```

The page lists the items on the left, with the PDF viewer on the right.

- **Tabs:** **Golden (40)** and **Synthetic spot check (20)**. The spot check is a fixed random
  sample of the 150 synthetic retrieval questions.
- **Filters:** **All**, **Pending**, **Done**.
- **Show page** opens the cited document at the cited page. Use ⌘F in the viewer to find the quote.
- **Keys:**

  | Key | Action |
  |---|---|
  | `j` / `k` | next / previous item |
  | `a` | accept |
  | `e` | save your fix |
  | `r` | reject |

Every decision is written straight into the dataset file with a timestamp. When you fix an item,
the generated original is kept next to it under `original`, so the fix stays visible in git.

## What to check, by item type

| Type (count) | Expected | Accept when |
|---|---|---|
| `single_hop` (24) | answer | The question is clear on its own; the answer is correct and complete according to the cited page; the quote really is on that page |
| `multi_hop` (6) | answer | As above, and the answer genuinely needs both cited passages |
| `unanswerable` (5) | refuse | The corpus really does not answer it. Search the likely act for the key terms. "Why it must be refused" explains it |
| `cross_tenant` (2) | refuse | It asks about the other tenant's handbook ("Northwind"), which the main tenant must never see |
| `follow_up` (3) | answer | The history plus the question make sense as a conversation, and the answer fits the resolved question |

- **Fix** (`e`) instead of rejecting when the item is salvageable:
  - reword an ambiguous question;
  - complete a partial answer;
  - correct the page range (the page fields next to the evidence).
- **Reject** (`r`) when the question is not answerable from the page, is trivial or misleading, or
  duplicates another item. Write one sentence in **Notes** saying why.
- **The answer is a reference, not a script.** The eval scores citations and refusals, not wording.
  Do not polish phrasing.

**Synthetic spot check:** for each of the 20 items, answer one question: is the question sensible,
and does the cited page answer it? **OK** (`a`) or **Bad** (`r`). The spot check only labels the
synthetic set's quality in the results; it does not filter it.

## Progress

```bash
python3 -c "import json,collections; print(collections.Counter(json.loads(l)['review']['status'] for l in open('eval/datasets/golden_v1.jsonl')))"
```

The review is done when nothing is `pending`. Official numbers count `accepted` and `edited`
items. If more than about 8 are rejected, n drops below 32 and the intervals widen; consider
writing replacements by hand (same JSON shape, `review.status: accepted`).

## After the review

1. **Commit the dataset** (the review is part of the data):
   ```bash
   git add eval/datasets/golden_v1.jsonl eval/datasets/retrieval_synth_v1.jsonl
   git commit -m "eval: review golden_v1 (N accepted, M edited, K rejected)"
   ```
2. **Run the official baseline.** Without `--include-pending`, it counts only reviewed items.
   ```bash
   make up                      # the database with the ingested eval corpus (smartdoc_eval)
   make eval-ingest             # only if smartdoc_eval is empty (a new volume): ≈ $0.01
   make eval                    # tier 1 + tier 2, ≈ $0.02; writes eval/results/<date>-<sha>.json
   ```
   Commit the results file. Its name has no `-pending` suffix, and its stamp records the git SHA,
   the config hash and the dataset hashes.
3. **Switch CI to reviewed items.** In `.github/workflows/ci.yml`, drop `--include-pending` from
   `make eval-ci`.
4. **Continue with calibration** ([calibration.md](calibration.md)).
